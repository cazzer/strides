# Strides

Browser-based running form analysis.

## Requirements

- Node.js >= 20.19.0 (required by the `openspec` CLI; see [openspec workflow](#openspec-workflow) below)

## Development

```bash
npm install
npm run dev      # start the Vite dev server
npm run build     # type-check (tsc -b) and produce a production build in dist/
npm run lint      # run ESLint
npm run test      # run the Vitest suite once
npm run preview   # preview a production build locally
```

Stack: React 19 + TypeScript, built and served with Vite, tested with Vitest and
React Testing Library, linted with ESLint (flat config) and formatted with
Prettier.

## OpenSpec workflow

This repo uses [OpenSpec](https://github.com/Fission-AI/OpenSpec) for
spec-driven change management. The `openspec/` directory (`config.yaml`,
plus `specs/` and `changes/` once they exist) and the Claude Code integration
under `.claude/commands/opsx/` and `.claude/skills/` were generated by
`openspec init --tools claude` and should be treated as generated output —
don't hand-edit the generated command/skill files. Note: the `claude` tool
option does not create or modify `CLAUDE.md`/`AGENTS.md` — that marker-block
integration is a separate `--tools agents` option we did not select. The
Claude Code integration here is entirely the command/skill files above.

Install the CLI once (or use `npx @fission-ai/openspec@latest <command>`):

```bash
npm install -g @fission-ai/openspec@latest
```

Contributor workflow for a change:

1. **Create a change** — `openspec new change <name>` scaffolds
   `openspec/changes/<name>/`. In Claude Code, `/opsx:propose "<idea>"` does
   this and drafts the proposal/spec/design/tasks artifacts in one step.
2. **Fill in the artifacts** — a change moves through `proposal` → `specs` /
   `design` → `tasks` (check progress with
   `openspec status --change <name>`). Use `/opsx:explore` and
   `/opsx:update` in Claude Code to iterate on these.
3. **Implement the tasks**, then apply/sync the change
   (`/opsx:apply` or `/opsx:sync` in Claude Code).
4. **Validate** — `openspec validate --all` should report no failures before
   archiving.
5. **Archive** — `openspec archive <name>` (or `/opsx:archive` in Claude
   Code) folds the change into the main specs and moves it out of
   `openspec/changes/`.

Run `openspec validate --all` at any time to check every change/spec; a
fresh scaffold with no changes yet reports "No items found to validate."
